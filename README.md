# Unreliable Map（あてにならない地図）v0.1

不完全な地図と曖昧な記録を頼りに、未知を信じるか疑うかを自分の責任で選ぶテキストローグ。
`unreliable_map_spec_v0.1.md` の検証プロトタイプ実装。

## 遊び方

```sh
npm install
npm run dev      # → 表示されたURLをブラウザで開く
```

- ボタンまたはキーボード（矢印キー＝移動、数字キー＝行動選択）で操作。
- 1潜行 = 開始→脱出/死亡。死んだら/生還したら「もう一度潜る」で、**同じ性格・別の迷宮**へ。
- 同じ潜行を再現するには `?seed=<数値>`（シードは起動時にコンソールに出る）。

### 賭けについて（v0.2）

- **宝箱** `[` は開けるまで中身が分からない（当たり＝剣・薬・糧食 / 外れ＝毒針・潜むもの・空）。
- **泉** `~` は飲むまで水の良し悪しが分からない。見た目は同じ。
- 手元の記録は箱と水の安全性を主張する——信じるか、疑うか。「調べる」で自分の見立て
  （気配帯の情報）を作り、確度の違う情報源を突き合わせられる。
- **視界は嘘をつかない。だが視界では分からないことがある。** 答えを知るのは、賭けた者だけ。
- 敵は必ず何かを持っている（金属系＝剣、獣＝糧食、影＝薬）。記録や気配が
  「奴は何かを運んでいる」と匂わせる——危険度と報酬を天秤にかけて挑むかを決める。
- 得物には段階がある（素手 ＜ 傷んだ短剣 ＜ 剣）。激しい戦いで刃は欠ける。
- 松明には予備がある。尽きてからが本当の暗闇で、暗闇の戦闘は大きく不利。

### 敵について（v0.1.1）

- 敵は**動く**。視線が通ればこちらに気づき、「最後に見た位置」を追ってくる（全知ではない）。
  角を曲がって視線を切れば、数ターンで見失って諦める。
- 金属系は強いが**重くて遅い**（1ターンおきにしか動けない）＝走れば振り切れる。
- 敵がマップに `&` で見えるのは**いま視界内にいる時だけ**。地形の記憶は残るが、動くものの過去の目撃位置は当てにならない。
- 遭遇時に「退く」と実際に1歩下がって距離を作る。追われながらでも、階段を降りれば振り切れる。

## 開発者向け

```sh
npm run sim        # 受け入れ条件の自動検証（再現性・ラベル的中率の帯・ループ完走 §13）
npm run sim:skill  # スキル実験: 挑む/避ける/地図を読むbotの生還率比較（判断が結果を動かすか）
npm run build      # 型チェック＋本番ビルド
```

**デバッグ表示**: `?debug=1` で起動、またはプレイ中にバッククォート（`` ` ``）でトグル。
内部確率・危険度リスク・敵の追跡状態・情報のHOLD/MISSなど、隠しパラメータをすべて画面に出す
（通常プレイでは一切出ない＝憲法5は維持）。

計測フック（§12・プレイヤー非表示）はブラウザのコンソールから:

- `window.__telemetry` … 現在の潜行の構造化ログ
- `window.dumpTelemetry()` … JSON出力＋ラベル別的中率の集計表

## 構成（§4.1）

```
src/
  core/            # 純ロジック。UI・DOM非依存。乱数は注入されたPRNGのみ
    rng.ts         # シード付きPRNG（mulberry32）。Math.random禁止（§4.2）
    character.ts   # DungeonCharacter（迷宮の性格）＝共有・記憶される単位（§5）
    generate.ts    # 性格＋runSeed → DungeonInstance
    hearsay.ts     # 古地図・噂＝別インスタンス由来の劣化記録（§9.3）
    confidence.ts  # 情報源→内部確率→信頼度ラベル（§6）
    danger.ts      # プレイヤー状態＋敵→危険度ラベル（§7）
    resolve.ts     # 当否解決と外れ方の重み（§8）
    state.ts       # ゲーム状態・ターンループ（§10・§11）
    telemetry.ts   # 計測フック（§12）
  ui/
    render.ts      # 画面テキスト組み立て
    input.ts       # 行動ボタン・キーボード
  main.ts
sim/check.ts       # 受け入れ条件のセルフチェック（§13）
```

## 設計メモ

- 内部確率・リスクは数値で持つが、**UIには言葉のラベルしか出さない**（憲法5）。
  ラベルは確率帯の正直な量子化なので、遊ぶほど「怪しい≒五分」が体で学べる（憲法6）。
- 古地図・メモの当否は**生成時に決定論的に解決**され、外れは「枯れた泉」「崩落」「罠の残骸」
  として実地形に理由ごと植え込まれる。踏破・視界が嘘をつくことは決してない（憲法1・2）。
- 「完全な誤情報」だけは、同じ性格・別シードで生成した兄弟インスタンス（＝別の潜行の記録）由来。
- 敵は動くため、敵についての情報は位置ではなく**敵本体の目視/撃破**で検証される。
  「位置ズレ」は動く敵には意味を成さないので、敵情報の外れ方は誤認・誤情報のみ。
- 敗北時の死亡/重傷の内訳はリスク連動（`deathShare = 0.25 + 0.55×risk`）。
  ラベル帯（§7＝死亡/重傷の合計率）は不変のまま、「死の気配に挑む＝本当に死ぬ」を鋭くしている。
- スキル実験（`npm run sim:skill`・各1000潜行）: 常に挑むbot 27.2% ＜ 危険度を読むbot 30.9% ＜
  記録を読むbot **38.2%**（宝持ち帰り 32.3→46.8%）。
  箱と水——「検証行為そのものがリスクを持つ判断」に情報を付けたことで、
  記録を読むことが機構的に報われている（v0.2の主眼）。
- 記録の検証タイミングも判断に従う: 箱の中身と水の安全性についての記録は、
  開ける/飲むまで〔検証済み〕にならない。警告を信じて開けなければ、真偽は永遠に分からない。
